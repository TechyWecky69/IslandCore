# IslandCore Dashboard Website 2.0.0

This is the separate UI for the IslandCore Dashboard API.

The visual dashboard remains the same dark two-column design as the previous dashboard. The Terminal page has been removed. The Dashboard, Chat and Trades pages now communicate directly with the Minecraft plugin's secure API.

## Files

- `login.html` — login screen
- `index.html` — server dashboard
- `chat.html` — chat history
- `trades.html` — trade history
- `style.css` — existing dashboard styling
- `config.js` — API URL and application key
- `app.js` — shared API/session client

## Configure

Edit `config.js`:

```js
window.DASHBOARD_CONFIG = {
  apiBase: "https://127.0.0.1:8765",
  applicationKey: "PASTE_THE_APPLICATION_KEY_FROM_CONFIG_YML_HERE"
};
```

Use the exact application key generated by the plugin.

For production, use an HTTPS API URL with a certificate trusted by the device.

## Login/session model

The browser sends the username/password only to:

`POST /api/auth/login`

The API returns a short-lived bearer session token. The website keeps that token in `sessionStorage`, not in a permanent cookie. Closing the browser/tab removes the session in normal browser use.

Every protected API request sends the application key and bearer token.

## Running the website

Because this is a static site, it can be hosted by any static web server or packaged into a native application later.

For local testing, serve the folder through a local HTTP server rather than opening HTML files directly. For example, with Python installed:

```text
python -m http.server 8080
```

Then open:

`http://127.0.0.1:8080/login.html`

The API's `api.allowed-origin` should be changed from `*` to the real website origin for production.

## Native app note

The application key is an application authorization secret, not a replacement for user authentication. When this website becomes a desktop/mobile app, move the key into the platform's secure storage/keychain and keep it out of publicly distributed source files where possible.
